Risk rules and CSV

Translation Risk Scanner requires the exact columns expression, category, color, severity, explanation, suggestion and enabled. UTF-8/BOM and comma or semicolon delimiters are supported; rule IDs are generated in file order. A row is a possible review risk, not a confirmed translation error.

Language Interference rules and CSV

Language Interference Scanner requires the exact columns rule_id, expression, language, category, severity, color, explanation, suggestion and enabled. UTF-8/BOM and comma or semicolon delimiters are supported. Valid languages are da, nb, no and mixed; categories are RED, ORANGE and YELLOW. The bundled compatible example is data/examples/da_interference_rules.csv.

Running a scan

Select the source document and rule CSV, run the scanner, then compare marked Word text with the source and target context. A finding is a possible risk or interference, not proof of a confirmed translation error.

Interpreting findings

False friends and related-language interference can resemble correct cognates. Verify every highlighted occurrence against context and revise only when the evidence supports it.

Word Index and interference

Use frequency and stopword-filtered output to identify repeated terms and possible interference candidates; the index does not determine translation errors.

Building terminology resources

Create concepts, add terms with language and status, import mapped customer CSV rows, review possible duplicates and export canonical terminology.

First-run tutorial

The local tutorial uses bundled sample files and writes only to a user-selected or temporary local output directory. It does not upload manuscript or terminology content. Tutorial steps are a guided introduction; the full module procedures above describe validation and limitations.
